## Implemented Findings

### C1 — Prisma Error Handling Gap (Medium)

**Fix**: Created `common/filters/prisma-exception.filter.ts` with `@Catch(Prisma.PrismaClientKnownRequestError)` and an error map:

| Prisma Code | Mapped To | HTTP Status |
|-------------|-----------|-------------|
| P2002 (unique constraint) | `ConflictError` | 409 Conflict |
| P2025 (record not found) | `NotFoundError` | 404 Not Found |
| P1001 (connection unavailable) | Plain `Error` → ServiceUnavailable | 503 Service Unavailable |
| Unmapped codes | Re-thrown → `GlobalExceptionFilter` | 500 Internal Error |

Registered in `app.module.ts` as an `APP_FILTER` **before** `GlobalExceptionFilter` to take priority for Prisma errors.

### C2 — getErrorCode Status Map Incomplete (Low)

**Fix**: Added to `global-exception.filter.ts` status map:
- `HttpStatus.UNPROCESSABLE_ENTITY` → `"VALIDATION_ERROR"`
- `HttpStatus.SERVICE_UNAVAILABLE` → `"SERVICE_UNAVAILABLE"`
- `HttpStatus.GATEWAY_TIMEOUT` → `"GATEWAY_TIMEOUT"`

### S1 — Provider Error Body Leaked (Medium)

**Fix**: In `ai-gateway.service.ts:148-153`, replaced direct `result.error.message` with a sanitized generic message:

```
Before: `message: result.error.message`      // may contain provider internals
After:  `message: "AI provider temporarily unavailable"`  // sanitized
```

Full provider error details are logged server-side via `this.logger.warn` (rootLogger retained).

### S2 — No Correlation ID in Error Responses (Low)

**Fix**: Added `correlationId` field to the `GlobalExceptionFilter` error response body, read from `request.headers["x-correlation-id"]`. Also fixed the `ErrorResponse` interface to match the runtime response shape.

### A1 — AuthGuard Generic Re-throw (Low)

**Fix**: Added `Logger` to `AuthGuard`; catch block now logs the original JWT verification error with `this.logger.warn` before re-throwing the generic `UnauthorizedError`.

### A3 — Inline Comment Artifact (Informational)

**Fix**: Removed stale `/* deleted */` inline comment from `document.service.ts:145`.
