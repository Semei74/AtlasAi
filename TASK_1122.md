## ADRs

### ADR-001: OrganizationAuditService Should Be Removed

- **Decision:** Remove `organization-audit.service.ts` as dead code.
- **Status:** Proposed
- **Context:** The service is `@Injectable()` with a complete implementation including event types, an `emit()` method, and structured logging. However, it is never imported by any service, never registered in any module, and never instantiated anywhere in the codebase.
- **Consequences:** Removing the file eliminates clutter. If audit logging is needed in the future, the implementation should be recreated using domain events rather than a standalone service.

### ADR-002: Workflow Executions Map Needs Eviction

- **Decision:** Add cleanup for the `executions` Map in WorkflowRuntimeService when executions complete, fail, or are cancelled.
- **Status:** Proposed
- **Context:** The `executions` Map grows monotonically with every workflow execution. The companion `abortControllers` Map is properly cleaned up, but `executions` is never pruned.
- **Consequences:** Adding `this.executions.delete(executionId)` alongside the existing `this.abortControllers.delete(executionId)` in the 3 terminal code paths will prevent the memory leak.

### ADR-003: Gemini API Key Should Use Header Not URL Parameter

- **Decision:** Move Gemini API key from URL query parameter to `x-goog-api-key` HTTP header.
- **Status:** Proposed
- **Context:** Gemini is the only AI provider that transmits its API key in the URL (`?key=${key}`). All other providers (OpenAI, Anthropic, Mistral, xAI, DeepSeek, Groq) use `Authorization: Bearer`. URL parameters can leak in server access logs, proxy logs, browser history, and Referer headers.
- **Consequences:** Changing from URL parameter to header reduces exposure surface. Google's Gemini API supports both `x-goog-api-key` header and `?key=` query parameter.
