## Objective

Make the AtlasAI monorepo fully buildable and certifiable: `pnpm install`, `pnpm lint`,
`pnpm typecheck`, and `pnpm build` must all pass for every workspace package. This task closed out
the remaining frontend infrastructure defects in the Tamagui-based design system (`@atlas/ui`), the
Next.js web app (`@atlas/web`), the observability package (`@atlas/observability`), and the hooks
package (`@atlas/hooks`), plus the root tooling (ESLint config, Turbo, pnpm workspace).

## Existing Architecture

- **Design system**: `packages/ui` exposes Tamagui primitives (`Text`, `Button`, `Stack`, `Card`,
  `Heading`, `Input`, `Avatar`, `Spinner`, `Divider`, `Surface`) wrapping `tamagui` components, plus
  `tamaguiConfig` via `createTamagui`.
- **Web app**: `apps/web` is a Next.js 15 (App Router) + React 19 application using
  `@tamagui/next-plugin` (`withTamagui`), `@tamagui/next-theme` for theming, and a
  `NextTamaguiProvider` client wrapper.
- **Observability**: `packages/observability` wires PostHog (`posthog-js`) and Sentry.
- **Hooks**: `packages/hooks` provides a TanStack Query `QueryProvider`.
- **Tooling**: ESLint flat config (`eslint.config.js`, `typescript-eslint` `strictTypeChecked`),
  Turbo (`turbo.json`), pnpm workspace with `overrides`.

## Identified Problems

1. **Tamagui prop types unusable (root cause).** Every Tamagui component's prop type
   (`WithShorthands<WithThemeValues<TextStylePropsBase>>`, etc.) resolved to a type with an index
   signature `[k: string]: undefined`. Any prop spread into a Tamagui component — including inline
   literals and `GetProps<typeof X>` — failed with
   `Property '<x>' is incompatible with index signature. Type '...' is not assignable to type 'undefined'`.
   This broke all `@atlas/ui` primitives and the entire web build's type-checking.
2. **Invalid `createTamagui` option.** `packages/ui/src/tamagui.config.ts` passed
   `settings: { disableRootThemeClass: true }`. That key does **not** exist in
   `Partial<GenericTamaguiSettings>` for `@tamagui/web@2.4.6`, so `createTamagui`'s argument didn't
   match its parameter. TypeScript then inferred the return type of `createTamagui` as `any`,
   poisoning the global `TamaguiCustomConfig` augmentation. Because
   `Shorthands = Narrow<TamaguiConfig["shorthands"]>` resolved to `any`, `keyof Shorthands` became
   `string`, and `WithShorthands` amplified that into the fatal `[k: string]: undefined` index
   signature on **every** Tamagui component.
3. **PostHog SSR crash.** `posthog.init` ran at module scope during Next.js server-side
   prerender/collection, referencing browser globals and throwing.
4. **`QueryClient` serialization error.** `packages/hooks` created a `QueryClient` class instance at
   module scope and passed it into `QueryClientProvider` inside a client component rendered by a
   server layout, violating Next.js RSC serialization ("Only plain objects … can be passed to Client
   Components from Server Components").
5. **Turbo missing.** `turbo` was referenced by `turbo.json` but not installed; root scripts used
   `pnpm -r` instead of `turbo run`.
6. **ESLint config gaps.** Generated files (`next-env.d.ts`, `.wxt/**`) were linted; `apps/web`
   lacked the `no-unsafe-*` relaxations needed for Next's loosely-typed `next.config.ts` webpack
   callback; several rule violations existed in new code.
7. **Sentry instrumentation.** `apps/web/instrumentation.ts` used `initSentry` from
   `@atlas/observability` (browser-only) in the Node.js runtime and had lint issues.

## Implemented Solution

### 1. Fixed the Tamagui type defect at its root (TASK-1128 primary blocker)

- `packages/ui/src/tamagui.config.ts`: replaced `settings: { disableRootThemeClass: true }` with
  `settings: {}`. This lets `createTamagui` infer a correct config type, so `TamaguiCustomConfig` is
  no longer `any`, `Shorthands` resolves to a finite key set, and the `[k: string]: undefined` index
  signature disappears from all Tamagui component prop types. **No library upgrades, no `any`, no
  disabled checks.**
- Rewrote the UI primitives (`text`, `button`, `card`, `avatar`, `divider`, `input`, `spinner`,
  `stack`, `heading`) to type their props via `ComponentProps<typeof TamaguiX>` combined with
  `WithoutIndex`/`WithChildren` helpers (`packages/ui/src/primitives/props.ts`) so `children` keeps
  its correct type. The unnecessary `as` casts were removed after the root cause was fixed (verified
  by `eslint --fix`).

### 2. PostHog SSR-safe initialization (`packages/observability/src/posthog.tsx`)

- Marked the provider `"use client"`.
- `posthog-js` is now imported **dynamically** inside `useEffect` (guarded by `apiKey`), instead of
  at module top-level. When no API key is present (build time), the provider renders `children`
  directly without mounting `PHProvider`, so no browser globals are touched during SSR.

### 3. RSC-safe QueryClient (`packages/hooks`)

- `packages/hooks/src/query-client.ts`: split into `createQueryClient()` factory +
  `queryClientOptions`; removed the module-scoped instance.
- `packages/hooks/src/query-provider.tsx`: marked `"use client"` and instantiates the client via
  `useState(createQueryClient)`, eliminating the serializable class instance crossing the
  Server→Client boundary.

### 4. Sentry instrumentation (`apps/web/instrumentation.ts`)

- Uses `@sentry/nextjs` `Sentry.init` directly for the `nodejs` runtime; removed the browser-only
  `initSentry` dependency in the server context. Fixed lint issues (`require-await`,
  `no-unnecessary-condition` on `process.env` typings).

### 5. Web build / Next config (`apps/web/next.config.ts`)

- Typed the `webpack` callback `(config, { isServer })`.
- Added `@tamagui/web` to `transpilePackages` so its React references resolve correctly in the
  server bundle (prevents the `createContext is not a function` SSR module-eval error).
- Kept the `react-native$` → `react-native-web` alias (client) and `react-native` →
  `react-native-web` resolve alias (server) for proper Tamagui web rendering.
- Auth login page marked `"use client"` and wrapped so Tamagui's `Text` renders inside a
  `TamaguiProvider` (required by Tamagui for theming).

### 6. Turbo (`package.json`, root)

- Added `turbo` as a root devDependency and switched root scripts (`build`, `dev`, `start`, `lint`,
  `lint:fix`, `typecheck`, `test`, `test:watch`, `test:e2e`, `clean`, `setup`) from `pnpm -r` to
  `turbo run`.

### 7. ESLint config (`eslint.config.js`)

- Added `**/next-env.d.ts`, `**/.wxt/**`, and `apps/extension/types/**` to global ignores
  (generated/third-party type files).
- Added `apps/web/**` to the group that relaxes `no-unsafe-*` rules (required for Next's inherently
  loosely-typed `next.config.ts` webpack callback).

## Architectural Decisions

- **Fix root cause, not symptoms.** The Tamagui index-signature defect was a type-inference poison
  from an invalid `createTamagui` option, not a Tamagui/React version incompatibility. Avoided
  unnecessary library downgrades (TypeScript and `react-native` were temporarily pinned and then
  reverted after confirming they were not required — build is green without them).
- **SSR safety.** PostHog and QueryClient were made SSR-safe by deferring side effects to
  `useEffect` / component scope rather than module scope.
- **No `any`, no disabled checks.** The `WithoutIndex` helper replaces any `as any`-style workaround
  for the (now-fixed) prop types.
